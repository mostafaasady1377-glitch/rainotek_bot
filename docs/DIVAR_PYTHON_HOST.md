# استقرار رابط انتقال روی هاست پایتون

این سرویس باید کنار بات و با همان دیتابیس موجودی و پیشنهادهای کارشناسان اجرا شود. یک هاست جدا با دیتابیس کپی‌شده، اتصال زنده ایجاد نمی‌کند.

نیازها: اجرای دائمی فرایند Python، دیسک پایدار، دامنه HTTPS، و امکان اجرای همزمان بات و سرویس aiohttp. هاست صرفاً WSGI یا فاقد فرایند دائمی برای این ساختار کافی نیست.

دستور سرویس از ریشه پروژه:

    python -m divar_campaign.handoff_server

برای هاستی که پورت را از متغیر PORT تعیین می‌کند، سرویس آن را می‌خواند. فقط پشت HTTPS و پراکسی هاست، DIVAR_HANDOFF_HOST=0.0.0.0 تعیین شود. روی سیستم محلی پیش‌فرض 127.0.0.1 باقی می‌ماند.

در محیط بات:

    DIVAR_HANDOFF_BASE_URL=https://YOUR-DOMAIN

کل پوشه bot/assets/divar-gallery و دیتابیس‌های اصلی و scratch/divar-campaign/seller-review.sqlite3 باید پایدار و مشترک باشند. اطلاعات نشست دیوار و کد ورود در سرور نگهداری نمی‌شود.

بررسی واقعی: سلامت /health، سپس دریافت بسته یک آگهی تأییدشده توسط افزونه، بازکردن فرم همان کسب‌وکار و تأیید عنوان، توضیحات، قیمت و پایان آپلود ۱۵ عکس. پاسخ سلامت به‌تنهایی اثبات انتقال نیست.

نصب Chrome: chrome://extensions ← Developer mode ← Load unpacked ← پوشه browser_extensions/divar-handoff. سپس دامنه سرویس در popup افزونه ثبت و مجوز همان دامنه تأیید شود. این افزونه سفارشی است و نصب و مجوز آن باید توسط کاربر تأیید شود.

ثبت نهایی، پرداخت و انتشار با کارشناس است. نشست دیوار ممکن است منقضی شود و ورود مجدد بخواهد.
