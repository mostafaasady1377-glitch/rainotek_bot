# انتقال آگهی راینوتک به مرورگر کارشناس

این نسخه فرم را پر می‌کند؛ ثبت آگهی، پرداخت یا انتشار انجام نمی‌دهد. آزمون زنده روی حساب‌های کارشناسان هنوز انجام نشده است.

## راه‌اندازی مدیر

1. سرویس `python -m divar_campaign.handoff_server` را با وابستگی‌های پروژه روی همان دیتابیس بات اجرا کنید.
2. آن را پشت دامنهٔ HTTPS اختصاصی و reverse proxy روی `127.0.0.1:8769` قرار دهید؛ access log شامل Authorization نباشد و محدودیت درخواست در proxy فعال باشد.
3. `DIVAR_HANDOFF_BASE_URL=https://YOUR-HANDOFF-DOMAIN` را در محیط سرویس بات تعریف کنید. این متغیر از محیط سیستم خوانده می‌شود؛ صرف افزودن به فایل env بدون بارگذاری در محیط کافی نیست.
4. هر کارشناس Chrome یا Edge دسکتاپ ← Extensions ← Developer mode ← Load unpacked ← همین پوشه را یک‌بار نصب کند.
5. در popup افزونه، همان دامنهٔ HTTPS را ثبت و دسترسی آن دامنه را تأیید کند. سپس در بات لینک فروشگاه خودش را ثبت کند.

## استفاده

مسیر فروشگاه هر کارشناس در دیتابیس دائمی است و پس از دریافت آگهی، پایان بازه یا restart پاک نمی‌شود.
برای آگهی‌های بعدی نیازی به ارسال دوبارهٔ لینک فروشگاه نیست. فقط مجوز دریافت بستهٔ هر آگهی
کوتاه‌مدت و یک‌بارمصرف است؛ این مجوز از مسیر دائمی فروشگاه مستقل است.

پیشنهاد اختصاصی ← تأیید و بررسی انتقال ← لینک انتقال به فروشگاه من.
لینک باید در همان مرورگر دارای افزونه باز شود، نه مرورگر داخلی تلگرام.
کارشناس یک‌بار در دیوار وارد می‌شود؛ انقضای نشست ممکن است ورود مجدد بخواهد.
از پنل همان کسب‌وکار ثبت آگهی را باز می‌کند؛ افزونه فیلدهای قابل شناسایی و عکس‌ها را خودکار آماده می‌کند. دکمهٔ «پرکردن فیلدهای این صفحه» برای بررسی مجدد دستی باقی می‌ماند.
عنوان، متن و قیمت فیلدهای شناسایی‌شده پر می‌شوند؛ ۱۵ تصویر گالری محلی با کنترل hash به input عکس فرستاده می‌شوند: دو تصویر فروشگاهی در ابتدا و ۱۳ تصویر لپ‌تاپ تکی پس از آن.
پایان آپلود، وضعیت دستگاه، نقشه و فیلدهای دیگر باید در صفحه بررسی شوند. افزونه خودش دکمهٔ مرحلهٔ بعد، ثبت یا پرداخت را نمی‌زند.

## حدود نسخه

- هر تب یک بستهٔ مستقل دارد؛ بسته‌ها پس از بسته‌شدن مرورگر حذف می‌شوند.
- لینک ۱۵ دقیقه یا تا پایان بازه اعتبار دارد و یک‌بارمصرف است؛ قیمت و موجودی موقع دریافت دوباره بررسی می‌شود.
- عکس‌ها از گالری `bot/assets/divar-gallery/manifest.json` می‌آیند؛ نبودن، تغییر hash یا تعداد نامعتبر فایل‌ها انتقال را متوقف می‌کند.
- ثبت لینک اثبات مالکیت فروشگاه نیست؛ خود دیوار دسترسی حساب مرورگر را تعیین می‌کند.
- افزونه فقط فرم `new/PREMIUM_PANEL/..._BUSINESS_ID` همان کسب‌وکار را پر می‌کند و فیلد غیرخالی متفاوت را بازنویسی نمی‌کند.
- ارسال فایل به input به معنی اتمام آپلود نیست؛ خطا/محدودیت دیوار باید بررسی شود.
- وضعیت `browser_package_delivered` فقط دریافت بسته توسط افزونه است، نه ذخیره آگهی در پنل.
- بدون دامنهٔ HTTPS و نصب افزونه، انتقال خودکار فعال نیست؛ لینک عادی فقط پنل فروشگاه را باز می‌کند.
